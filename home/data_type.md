---
title: 資料型態使用準則
---
##	**可明確判定為基礎型態 (如int、long、boolean、double、decimal、byte等) 時，不可使用string。**

若資料型態可以直接使用基礎型態，比如整數型態、浮點數型態、```true```或```false```等等，不應使用字串來表示，主要原因是若用字串表示，在進行運算處理時還要先將字串轉型為特定型態，無形中會消耗許多系統效能，整體速度也會因此被拖慢，因此除非確有必要，不應使用字串來表示所有資料。

```csharp
// OK
int amount = 100000;
double rate = 0.05;
int outcome = amount * (1+rate);
// Don't
string amount = "100000";
string rate = "0.05";
string outcome = (Convert.ToInt32(amount) * (1 + Convert.ToDouble(rate))).ToString();
```


> 最常見會用字串表示的是日期時間 (DateTime)，由於日期時間的特性，較有可能會使用特定字串如```2023-04-10```、```2023-04-10 11:15:49```或是```15:42:39```等格式，然而轉換成字串的時間應在要顯示於使用者介面的時候才進行，資料處理時仍應使用```DateTime```型態，以加速日期時間資料的處理。

##	**除非特別必要並加入註解敍明理由外，不可使用弱型態 (Weakness Type) 物件。**

弱型態是指```object```型態，這個型態允許容納所有型態的資料，也因此導致它有很大的不確定，且使用```object```型態與其他型態交換資料時，會誘發Framework的Boxing與Unboxing機制，使得處理效能會受到相當的影響，因此除非確有必要，不應使用弱型態作為變數型態。


> 若是作為函數的參數，則```object```型態確實有必要之處，但應盡量限縮於無法使用泛型或使用泛型反而降低可維護性或提升複雜度的情況。

##	**集合物件應採用具列舉性質 (如IEnumerable) 之介面實作之物件，並應使用泛型方法。**

集合物件 (Collections) 係作為儲存與管理多份資料的型態，.NET Framework內建的型態，基本上都有實作```IEnumberable```，因此可直接依實際需求選用，並且可以支援迭代模式 (Iteration Pattern)，能直接使用 foreach 進行內容的巡覽，而不必再使用 for 處理，在資料處理上相對便利。

若集合具有泛型版本時，以使用泛型版本為優先，因為使用泛型版本可以避免因Boxing/Unboxing產生的效能損耗。

##	**匿名型別應只用於串接複雜型物件集合 (如LINQ所產生之結果物件)，且應盡可能控制在同一個區塊內使用。**

匿名型別 (Anonymous Type) 是 C# 的功能之一，它可以在不宣告類別型態的情況下，直接在程式中產生類別，例如：

```csharp
var item = new {
  name = "Mary",
  email = "mary@kingfor.com.tw"
};
```

匿名型別雖然很方便，但以在同一個區塊 (如函數) 內使用為原則，亦可結合如 JSON Serializer 進行序列化，可減少額外撰寫與管理類別的負擔。


##	**編譯時期決議之型別 (如var) 可廣泛使用於程式內，但若因語意、辨識或避免誤用時，仍應使用明確型別宣告。**

編譯時期決議的型別，會在程式編譯期間由編譯器將變數轉換為等號右方指定的變數型態，例如：

```csharp
var i = 10;
var j = 10.0d;
var k = 10.0m;
```

會被轉換為

```csharp
int i = 10;
double j = 10.0;
decimal k = 10.0;
```

![](images/2023-04-20-15-51-39.png)

使用```var```可大量減少需要的變數宣告，但要注意變數範圍的極限 (尤其是數值型態)，否則會誤判轉換的資料型態，例如：


```csharp
var i = 2147483647;
var j = 2147483648; // 超過 int 的值域
```

會被轉換為

```csharp
int i = 2147483647;
uint j = 2147483648;
```

![](images/2023-04-20-15-55-21.png)

另外，若是等號右邊無值，或是要初始化的型態是特定型態時，則不能使用```var```，例如：

```csharp
long length = 123; // 使用 var 時會轉成 int
IService service = new WeatherService(); // 使用 var 時會轉成 WeatherService
```

##	**動態解析型別 (如dynamic) 應限縮使用範圍，除特定情境以註解敍明理由外，以不使用為原則。**

動態解析型別```dynamic```類似匿名型態，它可以容納以key-value對應的資料項目，但它是在執行時期 (Runtime) 才會被 CLR 解析，因此在編譯時期不會發現可能有問題。
另外，```dynamic```由於是執行時期決議，也無法在Visual Studio中用成員列舉方式來得知它的內容，只能透過執行來判斷，容易衍生其他問題。
因此，```dynamic```以不使用為原則，若要使用需增加註解說明，以降低誤用的機率。

##	**型態之轉換方針**

1. 將字串轉換成非字串型態時，如框架有提供嘗試轉換之方法 (如int.TryParse) 時，應使用之，如不使用，亦應編寫捕捉轉換失敗之例外處理程式。
2. 型態間之轉換應考慮下列情境：
- 來源型態為null。
- 來源型態精度較目標型態小 (例如單精度浮點數轉換成雙精度浮點數)，或是轉換後有損及資料之可能。
- 來源型態可預期無法成功轉換為目標型態。
3.	整數四捨五入、無條件進位或無條件捨去之判斷，需確實與功能需求對應，如有需求不明之處，應與軟體開發團隊主管討論之。

## **如變數、參數等為可允許null時，應使用可允許null之型態(例如Nullable<T>)予以宣告；但若null範圍可控制於一定範圍內時得不在此限。**

基礎型別中，只有```string```預設允許```null```，其他的預設並不允許，但大多數的情況下又會需要添加```null```作為有值與否的判斷 (例如```default(int)```的值為0，無法作為有值判斷與否的基準)，因此若需要加上```null```能力時，應使用```Nullable<T>```型態，它可以使用```HasValue```屬性判別是否有值，或是運用```??```作為```null```的替代檢測等。

![](images/2023-04-20-16-14-09.png)

若```null```的檢測能限制在一定範圍 (如只在函數內)，則可以考慮不使用```Nullable<T>```，但若是要用於其他地方，則應使用```Nullable<T>```較佳。

## **型態之判斷應以該程式語言所提供之功能，效能最佳者優先。**

型態的使用應考量值域、精度與可能的範圍綜合考量，結合前面所提不應使用字串包裝基礎型別的要求，以及對記憶體的使用決定要使用何種型別，以下為一些指南：

1. 能用日期時間就不要用字串。
2. 用於貨幣、金錢的，應使用```decimal```以防止可能的四捨五入掉碼問題。
3. 可能會突破```int```極限的，可用```long```來替代，例如 Ticks (時間的計量最小單位) 或是資料流的長度等。
