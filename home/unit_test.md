# 單元測試

1. **開發人員應針對類別的 public 方法撰寫單元測試 (Unit Test)，並可同時於本地與 CI/CD 環境中自動執行，以確認方法的實作正確無誤。**
2. **單元測試專案應為獨立的專案，並使用測試框架 (如 NUnit) 開發。**
3. **測試的輸入 (input) 與輸出 (output) 應依照規格設計，於單元測試程式中依 AAA 原則 (Arrange, Act, Assert；初始化、執行、評鑑) 進行初始化作業，執行被測試的方法以及驗證回傳值是否如預期 (expected)，若為 void 方法則確認是否有例外狀況。**
4. **可設計異常資料，確認方法面對異常資料時的反應，作為測試通過與否的條件之一。**
5. **避免在測試時使用過於複雜的邏輯 (例如在測試程式中才生成測試資料)。**
6. **不在同一個單元測試中測試兩個以上的方法 (一個測試一個方法)。**
7. **如有多個測試案例 (Test Case) 時，宜考慮以案例區分測試程式。**

# 整合測試

1. **測試案例若為兩個以上的類別互動時，應撰寫整合測試 (Integrated Test)，與單元測試相同，必須能於本地或由 CI/CD 自動化程序執行。**
2. **整合測試碼視測試案例與情境，可以不在相同的方案 (solution) 內，但若測試範圍未擴及不同方案 (solution) 時，得與單元測試程式放在相同的專案。**
3. **整合測試原則與單元測試相同，但測試對象為類別、元件與服務之間的互動，撰寫測試時宜確認測試範圍限縮於互動情境，且為需互動的最小情境範圍 (例如叫用 API、存取資料庫、讀寫檔案等)。**
4. **與單元測試相同，應適度納入異常資料的處置。**
